# Soenneker.Blob.Sas

Builds Azure Blob Storage URLs and read-only shared access signatures (SAS).

## Installation

```bash
dotnet add package Soenneker.Blob.Sas
```

## Configuration

```json
{
  "Environment": "Production",
  "Azure": {
    "Storage": {
      "Blob": {
        "AccountName": "<storage account name>",
        "AccountKey": "<storage account key>",
        "ConnectionString": "<connection string>"
      }
    }
  }
}
```

`AccountName` and `AccountKey` are required by the direct signing methods. `ConnectionString` is also required when using `GetSasUriWithClient` because that method obtains a configured `BlobClient`.

When `Environment` is `Local`, blob URLs use the Azurite endpoint at `http://127.0.0.1:10000/devstoreaccount1/`.

## Registration

```csharp
using Microsoft.Extensions.DependencyInjection;
using Soenneker.Blob.Sas.Registrars;

services.AddBlobSasUtilAsScoped();
```

`AddBlobSasUtilAsSingleton()` is also available.

## Usage

```csharp
using Soenneker.Blob.Sas.Abstract;

public sealed class DownloadLinks
{
    private readonly IBlobSasUtil _sas;

    public DownloadLinks(IBlobSasUtil sas)
    {
        _sas = sas;
    }

    public string GetInvoiceLink(string invoiceId)
    {
        return _sas.GetSasUri("invoices", $"{invoiceId}.pdf");
    }
}
```

Use `GetBlobUri` when the container or blob is already public and no signature is needed:

```csharp
string uri = sas.GetBlobUri("public-assets", "images/logo mark.svg");
```

## Method behavior

| Method | Result | Expiration and access |
| --- | --- | --- |
| `GetBlobUri` | Unsigned absolute blob URL | No token |
| `GetSasUri` | SAS URL signed directly with the configured account key | Read-only, one month |
| `GetSasUriWithClient` | SAS URL generated by a shared-key `BlobClient`, or `null` if it cannot sign | Read-only, one month |
| `GetAccountSasUri` | Account SAS appended to a Blob service URI | Blob container/object read and list, one hour |

SAS start times are backdated by five minutes to tolerate modest clock skew. Production signatures require HTTPS; the local Azurite flow permits HTTP.

## Security

- Treat every SAS URL as a credential until it expires. Do not write it to logs, analytics, exception messages, or persistent client storage.
- Return the URL only to callers allowed to read the referenced content.
- The account key can sign access to the storage account. Keep it in a secret provider rather than source control or ordinary configuration files.
- Prefer the narrow blob-level methods over `GetAccountSasUri` unless account-level listing is required.
- Revocation normally requires changing the account key unless the surrounding storage design uses a revocable access policy.
